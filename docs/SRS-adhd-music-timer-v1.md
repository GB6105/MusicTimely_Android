# 뮤직 타이머 모바일 앱 요구사항 명세서

- 문서 ID: MT-SRS-001
- 버전: 1.0 / 개발·QA용 초안
- 작성일: 2026-09-28 (Asia/Seoul)
- 기준: PRD-adhd-music-timer-v2.md, 문서 내부 버전 **v2.1**
- 적용 플랫폼: iOS / Android. 특정 개발 프레임워크에 종속되지 않는다.
- 구조: 독립 앱으로 실행 가능한 호스트 중립 모듈. 반려 에이전트·Untangle 탑재 가능.
- 시각 방향: 사용자 선택 **Chalk 뉴모피즘 + 검은색 돌출 레코드**.
- 폰트: **SUIT 권장, 미확정**. 디자인 토큰으로 교체 가능하게 한다.

> 이 문서는 PRD의 전략·가설을 구현 가능한 동작과 인수 기준으로 풀어 쓴다. 새로 정한 수치·충돌 해소안은 **개발 기본안(제안)**이며, 승인된 제품 결정으로 가장하지 않는다. 원본 PRD 및 ADR은 수정하지 않는다. 외부 서비스·스토어 정책의 최신 준수 여부를 인증하는 문서가 아니다.

## 0. 읽는 법과 근거 우선순위

1. 이 대화에서 사용자가 선택한 시각 방향은 이전 목업보다 우선한다.
2. 기능은 현행 PRD v2.1 및 ADR-0012를 따른다. v1 파일은 보관용이다.
3. PRD 내부 충돌은 §2의 개발 기본안으로 분리한다. 출시 전 PM·개발·디자인 검토 항목이다.
4. 2026-09-22 멘토링 문서는 제안·회의 기록이므로 요구사항으로 자동 승격하지 않는다.
5. 이미지 목업의 가상 곡명·재생 시각은 기술 지원 증거가 아니다.

| 표기 | 의미 |
|---|---|
| 필수 | 해당 범위 출시 시 충족해야 할 요구사항 |
| 조건부 | 명시된 기능 플래그·권한·소스 조건에서만 적용 |
| 후속 | 현재 코어 출시 범위 밖. 기본 OFF |
| 개발 기본안 | PRD의 빈틈을 메우기 위한 제안. 변경 가능하며 승인 필요 |
| FR / NFR / QA | 기능 / 비기능 / 검수 시나리오 식별자 |

### 0.1 용어

- **배정 시간:** 사용자가 이번에 쓰기로 정한 시간. 작업 완료 시간의 예측이 아니다.
- **실제 경과 시간:** 이 문서에서는 RUNNING 구간을 합친 **세션 측정 시간**. 실제 작업·집중·청취 시간과 동일하다고 주장하지 않는다.
- **D0:** 평균 곡 길이로 시간을 환산하는 방식. 외부 음악의 실제 재생 여부와 무관한 추정이다.
- **O0:** 앱 자체 플레이어가 제공하는 이벤트. 로컬 파일의 재생 상태와 곡 전환 등을 읽는다.
- **O2:** Android 외부 미디어 세션 관측. 후속 기능이며 앱별 지원 검증이 필요하다.
- **곡 분량:** 시간을 평균 곡 길이로 나눈 값. 실제로 들은 곡 수가 아니다.
- **배정 도달:** 타이머의 현재 목표에 도달한 상태. 자동으로 새 세션을 시작하거나 시간을 늘리지 않는다.

## 1. 제품 범위

### 1.1 핵심 사용자 흐름


작업 선택 → 시간 배정 → 곡 분량 환산 → 세션 시작
→ 잔여 확인 → 선택적 정지/재개 → 끝 예고 → 중립 결과

실제 화면 문구는 다음 순서로 구성한다.

1. “지금 할 일” 한 줄. 독립 앱에서는 비워도 시작 가능.
2. “얼마나 할까?” → 10 / 25 / 40분 / 직접 입력.
3. “25분 ≈ 약 7곡 분량” → 시작.
4. “약 4곡 분량 남음” + 09:24 경과 + 음악 실행 패널.
5. “대략 한 곡 분량 남았어요” → 배정 도달 → 마치기 / 직접 연장.
6. “배정 25분 · 세션 25분 / 약 7곡 분량”처럼 출처에 맞는 대조.

**금지:** “몇 곡 걸릴 것 같아?”, 추정치를 실제 청취로 단정, 집중도 점수, 스트릭, 초과 실패 판정, 타이머에 따른 외부 음악 제어.

### 1.2 릴리스 경계

| 항목 | 코어 출시(P1~P2) | 개인 음원 단계(P3) | 후속(P4/V2+) |
|---|---|---|---|
| 시간 배정·D0 환산·타이머·레코드 UI | 필수 | 유지 | 유지 |
| 외부 음악 앱 실행·수동 전환 폴백 | 필수 | 유지 | 앱별 확대 |
| 절차적 화이트/핑크 노이즈·음악 없음 | 필수 | 유지 | 음원 추가 검토 |
| 결과·일시정지·복원·생각 메모 | 필수 | 유지 | 유지 |
| 로컬 파일 선택·플레이리스트·반복(O0) | 구현 인터페이스 확보, 메뉴 숨김 | 필수 | 유지 |
| 현재 외부 곡 제목·정밀 재생 위치 | 제공 안 함 | 제공 안 함 | 검증된 O2에서 조건부 |
| Apple Music D1 / Spotify D2 | OFF | OFF | 정책·토큰·쿼터 검증 후 |
| iOS 타 앱 관측(O1) | OFF | OFF | 현재 범위에서 제외 |
| 커뮤니티·AI 음악·SNS·결제·계정 | 제외 | 제외 | 별도 PRD 필요 |

PRD §8은 로컬 파일을 V1 필수로, §13은 P3로 기술한다. **코어 미리보기에는 제외할 수 있지만, PRD V1 전체 완성을 주장하려면 P3까지 충족해야 한다.**

### 1.3 성공과 출시 판정 분리

- 기능 출시: 본 문서의 기능·접근성·데이터·복구 QA를 통과해야 한다.
- 제품 가치: MT-H2 등 PRD 실험으로 검증한다. QA 통과를 효과 입증으로 해석하지 않는다.
- 타이머 시작은 과제 착수의 증거가 아니다. 실험은 별도 동의와 과제 행동 정의가 필요하다.

## 2. 충돌·미확정 사항에 대한 개발 기본안

아래는 **새로운 제안**이다. 구현은 분기 가능한 설정으로 두되, 최종 출시 전에 검토 기록을 남긴다.

| 결정 ID | 문제와 근거 | 개발 기본안 | 출시 영향 |
|---|---|---|---|
| DEC-01 | MT-T4 자동 연장 금지 vs §2·MT-V7 초과 세션 사례 | 목표 도달 시 LIMIT_REACHED로 측정 정지. 사용자가 +5/+10/+15분을 탭한 경우만 같은 세션을 연장. 최초 배정은 보존 | 배정 도달 UX 승인 필요 |
| DEC-02 | MT-V8·R4 곡 수 장기 저장 금지 vs MT-V11 지난 작업 제안 | 명시적으로 허용한 **작업별 마지막 세션 시간(초) 1개**만 저장. 곡 수·평균·청취 이력은 저장하지 않고 현재 D0로 재환산 | 동의 없는 이력 제안 금지 |
| DEC-03 | MT-M6·§5.4 외부 정지 감지 vs O1/O2 범위 제외 | D0에서는 외부 정지를 알 수 없음. 세션 시간 기반 환산을 계속하며 “추정” 표시. 외부 정지에 맞춰 칩이 자동 정지한다고 약속하지 않음 | 코어 구현 필수 |

| DEC-06 | 노이즈 O0 “정확” vs 실제 곡 경계 없음 | 노이즈는 시간만 정확. “소리 구간” 또는 시간 표시, 실제 N곡 들었다는 표현 금지 | 모든 카피 적용 |
| DEC-07 | §12 곡 이벤트·초과율 분석 vs 곡 수 누적 금지 | 곡 이벤트는 메모리 내부 전용. 기본 분석은 비활성, 동의 시에도 곡 수·메타데이터 전송 제외 | 이벤트 허용목록 검수 |
| DEC-08 | §5.2 Apple Music 큐 준비 vs M4 외부 제어 금지 | 코어는 딥링크/수동 전환만. 사용자 탭이라도 큐 설정·SDK 재생을 코어에 넣지 않음 | D1 이후 별도 심사 |
| DEC-09 | MT-M9 알림 덕킹 vs 외부 음악 무간섭 | 기본 알림은 무음/선택적 진동. 외부 오디오 세션을 덕킹하려고 활성화하지 않음. OS 알림의 순간적 영향은 앱이 보장하지 못함 | 소리 알림 기본 OFF |
| DEC-10 | 분/곡 프리셋·OS 최소 버전 미정 | 초깃값 25분, 평균 곡 240초. 직접 시간 1~240분 정수. 곡 길이 60~1,800초. iOS 17+ / Android 10(API29)+를 검증 기준 제안 | 수치·지원범위 확인 |
| DEC-11 | PRD §7.3 D1 적극 유도 vs §7.1·13 후순위 | D0를 기본으로 출시. D1 업셀·로그인 유도 없음 | 초기 온보딩 단순화 |
| DEC-12 | 레코드 시안 vs MT-V2 잔여 칩 | 검은 레코드를 주 비주얼로 쓰되 그 아래 잔여 정보와 작은 칩을 유지. 레코드 회전을 실제 스트리밍 재생 표시로 오인시키지 않음 | 디자인 QA |

법적 단정도 승계하지 않는다. 재생을 제어하지 않는다고 정책 위험이 0이 되는 것은 아니며, 절차적 생성·로컬 파일도 코드·샘플·배포 방식에 따른 권리 검토가 필요하다.

## 4. 기능 요구사항과 인수 기준

각 행은 단위/통합/UI 테스트로 확인 가능한 계약이다. 세부 계산과 예외는 §5~§8을 함께 적용한다.

**승인 상태:** DEC를 인용하는 FR 및 그 QA는 해당 개발 기본안 채택을 전제로 한 **조건부 초안**이다. 특히 FR-005/006/010/011과 QA-09/10/30/31은 제품 결정 승인 전 확정된 출시 요구사항이 아니다. 착수 시 DEC를 승인하거나 대안을 정한 뒤 연결된 FR·QA를 함께 갱신한다. 아래 “필수” 표현은 이 승인된 버전에 대해 적용한다.

### 4.1 입력·배정

| ID | 요구사항 | 인수 기준 | 근거 |
|---|---|---|---|
| FR-001 | 독립 앱 작업 제목은 선택. 호스트 제목/ID는 불투명 값으로 수신 | 공백이면 “지금 하는 일”; 최대 100자(사용자 인지 문자), 두 줄 초과 말줄임·접근성 전체 낭독 | HC-1 |

## 5. 타이머 상태 머신

### 5.1 상태

- READY: 세션 시작 전. 배정 수정 가능.
- RUNNING: 세션 측정 중.
- PAUSED: 사용자 정지. 활성 측정 시간 증가 없음.
- LIMIT_REACHED: 목표 도달. 명시적 선택 대기. 활성 측정 시간 증가 없음.
- ENDED: 완료/중단 결과가 확정된 상태. 같은 세션을 재개하지 않음.
- RECOVERY_REQUIRED: 저장 상태 또는 시계 근거가 불충분하여 복원 선택 필요.

**음악 상태는 별도 머신:** unavailable / unknown / stopped / playing / interrupted. 외부 D0는 기본 unknown. 음악 상태 변경이 세션 머신을 전환하지 않는다.

| 현재 | 입력 | 다음 | 부수효과 |
|---|---|---|---|
| READY | START | RUNNING | 상태 원자 저장, 단일 알림 스케줄 생성 |
| RUNNING | PAUSE | PAUSED | 경과 확정, 목표 알림 취소, 자체 오디오 덕킹 |
| PAUSED | RESUME | RUNNING | 새 시간 anchor, 남은 시간 기준 알림 재예약 |
| RUNNING | REACH_LIMIT | LIMIT_REACHED | 측정 clamp, 예정 알림 정리, 자체 소리 fade-out |
| LIMIT_REACHED | EXTEND(delta) | RUNNING | 목표에 delta 추가, 최초 배정 유지, 새 cue cycle |
| RUNNING/PAUSED/LIMIT_REACHED | FINISH | ENDED | 최종 snapshot, 자체 소리 fade-out, 결과 콜백 |
| ENDED | START_AGAIN | READY | 새 세션 준비, 이전 결과 곡 데이터 폐기 |
| 모든 비종료 | INVALID_RECOVERY | RECOVERY_REQUIRED | 타이머/자체 재생 자동 시작 금지 |

- START/PAUSE/RESUME/FINISH는 commandId로 멱등 처리한다.
- **연장은 타이머만 재개한다.** 배정 도달에서 fade-out한 자체 소리는 별도 재생 탭이 있어야 다시 시작한다. O0 곡 이벤트 반영은 confirmed playing과 RUNNING이 모두 충족될 때만 재개한다. 외부 음악은 건드리지 않으며 D0의 시간 환산만 재개한다.
- 같은 tick에 목표 도달과 종료가 겹치면 경과를 목표까지 정규화한 뒤 FINISH 1회만 처리한다.
- 화면 뒤로가기/앱 전환은 FINISH가 아니다. 활성 세션 유지.
- 코어는 END_REASON을 completed(최초 배정 이상), user_ended(그 전 종료), abandoned(복구 포기)로 기록한다. 무한 모드는 user_ended, 완주율 분모 제외.
- 연장 수락은 과제 완료 선언이 아니다. “실제로 일을 끝냈다”는 값은 별도 자기보고 없으면 unknown.

### 5.2 시간 계산 계약

단위는 내부 millisecond 정수, 직렬화는 epoch millisecond와 누적 millisecond를 구분한다.

    E = accumulatedActiveMs + max(0, monotonicNow - runningAnchorMono)
    effectiveE = bounded ? min(E, currentTargetMs) : E
    remainingMs = bounded ? max(0, currentTargetMs - effectiveE) : null

- 상태 전이 때 accumulatedActiveMs와 anchor를 한 transaction으로 기록한다.
- 타이머 정확성의 기준은 UI의 setInterval 호출 횟수가 아니다. UI는 최대 1Hz로 파생값을 읽는다.
- elapsedMonotonicClock은 기기 sleep을 포함하는 적합한 플랫폼 시계를 사용한다. iOS/Android 실제 동작은 복원 스파이크로 검증한다.
- 같은 boot에서는 monotonic 차를 우선한다. 타임존·DST·수동 벽시계 변경으로 활성 시간이 변하면 안 된다. 예정 로컬 알림과 clock의 불일치가 확인되면 복귀 시 남은 시간 기준으로 재예약한다.
- 재부팅 등 monotonic 연속성을 증명할 수 없으면 wall-clock 복원값을 추정으로 취급하고 RECOVERY_REQUIRED로 보낸다. 사용자에게 “저장된 지점에서 이어가기 / 여기서 마치기” 제공.
- 강제 종료 후 소리 재생은 자동 복구하지 않는다. 세션 시간 복원과 별개다.
- 한계를 넘긴 백그라운드 세션은 target에서 LIMIT_REACHED로 복원. 알림 지연을 측정 시간에 더하지 않는다.
- 무한 모드의 비정상적으로 긴 복원 간격(기본 24시간 이상)은 자동 확정하지 않고 복구 확인. 임계는 개발 기본안.

## 6. 곡 환산과 O0 계산

### 6.1 D0의 단일 계산 규칙

- T: 최초 배정 초; G: 현재 목표 초; E: 세션 활성 경과 초; d: 시작 시 고정한 평균 곡 길이 초.
- 배정 표시 N = max(1, ceil(T / d)). 반드시 “약 N곡 분량”이라고 표시한다.
- 잔여 표시 R = max(0, ceil((G - E) / d)); 무한에서는 null.
- 경과 분량 U = E / d. 결과는 소수 첫째 자리까지 반올림하되 정수면 소수 생략.
- 구간 인덱스 I = floor(E / d) + 1. 목표에 도달하면 다음 구간을 새로 표시하지 않고 도달 상태를 표시한다.
- 칩은 floor(E / d)만큼 채우되 목표가 소수 구간인 마지막 칩은 E>=G에서 완료. 연장 후에는 최초/추가 배정을 구분하며 붉은 초과 색상을 쓰지 않는다.
- 숫자 반올림은 표현 전용. 목표 타이머는 절대 N×d로 변경하지 않는다.
- 실제 음악을 늦게 켜거나 중간에 끄더라도 D0는 이 사실을 모른다. 음악 청취 시간·곡 재생 위치로 해석하지 않는다.

**예시**

| 입력 | 기대 출력 |
|---|---|
| T=1,500초, d=240초 | 약 7곡 분량, 목표는 정확히 25분 |
| E=564초(09:24), G=1,500초 | 약 4곡 분량 남음, 경과 약 2.4곡 분량 |
| remaining=240초 | 한 곡 분량 남음 예고 1회 |
| T=120초, d=240초 | 시작 직후 “약 한 곡 분량으로 시작해요”; 시작과 동시에 방해 알림은 내지 않음 |
| E=G | 잔여 0, LIMIT_REACHED. “다음 곡 재생 중” 표시 없음 |

**소스별 표시 예외**

- 음악 없음: 기본 time_only. 곡 환산을 별도로 켠 경우에도 “시간 환산”으로 표시하고 청취·현재 곡 표시는 하지 않는다.
- 노이즈: 잔여 시간 또는 정한 길이의 가상 “소리 구간”을 표시한다. 노이즈 파형 처리 프레임이나 루프 버퍼를 곡으로 세지 않는다.
- 외부 D0: 자동 시작·정지 감지나 서비스별 실제 평균 길이 추론을 하지 않는다. 프리셋 근거는 사용자가 선택한 값뿐이다.
- 로컬 O0: 제목은 현재 재생 사실, 타이머 예고는 배정 시각에 관한 사실로 구분한다. skip/seek/일시정지로 큐가 달라지면 “이 곡이 끝나면 세션도 끝남”을 보장하지 않고 “마무리할 시간이 가까워요”로 안내한다.

### 6.2 수동 보정

보정은 음악과 타이머의 동기화가 아니라 사용자의 **표시 정렬**이다.

- k번째 곡/구간으로 보정하면 anchorIndex=k, anchorElapsed=E를 저장한다.
- 이후 표시 인덱스 = k + floor((E-anchorElapsed)/d). 분 단위 잔여와 끝 예고는 그대로다.
- 보정 시 “곡 표시만 맞췄어요. 정한 시간은 그대로예요.” 표시.
- 시간 환산 결과와 수동 곡 수를 섞어 하나의 실측값으로 만들지 않는다. 결과에서 기본 D0 값과 “사용자 보정” 출처를 구분한다.
- 보정 횟수·정확도를 성과 점수나 출시 품질 게이트로 쓰지 않는다.

### 6.3 자체 플레이어 O0(P3)

- durationMs, positionMs, playbackState, currentItemId, eventSequence 제공.
- 자연 종료로만 completedTracks 증가. skip/seek 명령 자체는 곡 완료로 세지 않는다. 이 값은 **활성 세션 중 정상 종료된 곡 경계 수**이지 곡 전체를 들었다는 증거가 아니다. 중간부터 듣거나 seek 후 끝난 곡도 있으므로 “완주 청취”라고 부르지 않는다.
- 한 곡 반복에서 같은 ID라도 자연 종료→restart 이벤트 1회마다 completedLoops 증가.
- 현재 곡의 부분 시간은 별도 currentItemPlayedMs. 여러 번 seek한 위치를 누적 청취 시간으로 오인하지 않는다.
- 세션 PAUSED/LIMIT_REACHED에서는 세션 연결 곡 카운터를 동결한다. 음악은 덕킹 등 정책에 따라 계속될 수 있지만 해당 구간은 세션 지표에 넣지 않는다.
- “현재 3번째 곡”과 “완료 2곡”은 다른 값이다. sessionIndex와 completedTracks를 혼용하지 않는다.
- 트랙 이벤트가 앱 종료·중단 중 누락됐다면 자동으로 완주곡을 보간하지 않는다. 결과 confidence=mixed 또는 unknown.
- 노이즈는 트랙이 아니다. 소리 활성 시간은 측정할 수 있어도 completedTracks는 null.
- 소스 변경 시 segment를 나눈다. 실제 곡 수와 D0 환산량을 덧셈해 단일 실측 곡 수로 표시하지 않는다.

### 6.4 외부 반복 D0 입력 계약

- SCR-09의 “다음 세션 표시 방식”에서 한 곡 반복을 선택할 수 있다. 아직 모르는 곡 길이를 필수로 요구하지 않으며, 입력하지 않으면 평균 곡 길이를 사용한다.
- 선택적 “반복할 곡 길이” 필드는 분:초 형식, 합계60~1,800초. loopDurationMs로 설정에 저장하고 시작 시 Allocation에 스냅샷한다. 재생 반복 설정 자체는 외부 앱에서 사용자가 한다.
- 표시 계산의 d는 loopDurationMs가 있으면 그 값, 없으면 durationPerUnitMs이다. 입력을 비우면 null. 진행 중 길이/모드를 바꾸면 다음 세션에 적용한다.
- “3분42초 반복”과 “실제로 반복 중”은 다른 정보다. D0는 후자를 알지 못하며 “약 N바퀴 분량”으로 표시한다.

### 6.5 예고 중복 방지

lastCueKey = sessionId + targetRevision. 목표별 한 번만 발생한다. 연장 시 targetRevision 증가. 보정·배경 전환·앱 재실행으로 같은 예고가 반복되지 않는다. 배정 도달 후 늦은 예고는 폐기하고 도달 알림만 유지한다.

## 7. 알림·오디오·플랫폼 계약

### 7.1 알림

- 알림 권한은 첫 세션 진입을 막지 않는다. 잠금 중 알림 기능을 사용하려는 맥락에서 설명 후 요청한다.
- 목표 알림은 플랫폼 또는 호스트 스케줄러로 예약한다. iOS 백그라운드 JS/상주 타이머를 요구하지 않는다.
- pause/finish/delete/extension마다 pending notification을 취소·대체한다.
- 알림 본문은 기본 “정한 시간이 지났어요.” 작업 제목·곡명·메모는 잠금 화면에 넣지 않는다.
- 포그라운드에서는 in-app cue만 표시하고 같은 알림을 중복 재생하지 않는다.
- 무한 모드에는 자동 목표 알림 없음. 사용자 취소 시 stale 알림도 없어야 한다.
- OS 절전·집중 모드·권한·강제 종료로 알림이 지연/누락될 수 있다. 정시 전달을 보장하지 않으며, 복원 계산과 알림 전달 성공을 분리한다.
- Android 정확한 알람 권한은 코어의 필수 조건으로 요구하지 않는다. 정확도 필요성·스토어 자격을 검토한 뒤 별도 옵션으로 판단한다.

### 7.2 checkpoint와 알림의 재조정

로컬 저장과 OS 알림 예약은 하나의 transaction이 될 수 없으므로 다음 절차를 앱 실행/복귀/상태 전이 재시도 때 수행한다.

1. checkpoint와 clock으로 권위 있는 세션 상태를 계산한다. RUNNING이어도 목표를 지났으면 LIMIT_REACHED로 원자 저장한다.
2. notificationKey=sessionId:targetRevision:kind를 사용한다. 모듈 소유의 이전 세션·이전 revision·PAUSED/ENDED/복구불명 상태 알림을 취소한다.
3. RUNNING이며 목표가 미래인 경우 현재 목표 알림을 같은 key로 upsert한다. 마지막 분량 예고를 OS에서도 쓰면 별도의 kind로 1개만 관리한다.
4. foreground cue와 delivered 알림의 중복은 cue key로 방지한다. OS가 앱 실행 전 이미 표시한 알림은 회수·정확히1회 표시를 완전히 보장할 수 없음을 명시한다.
5. 저장 성공·예약 실패 및 그 반대가 발생해도 재조정이 반복 가능해야 한다. 결과 확정 여부는 알림 성공 여부와 무관하다.

### 7.3 플랫폼별 접근

| 영역 | iOS | Android |
|---|---|---|
| 타이머 복원 | 로컬 state + 연속시간 근거; 프로세스 상주 의존 없음 | 동일 원칙, 앱 프로세스 생존 의존 없음 |
| 외부 앱 실행 | 검증된 Universal Link / 등록 scheme | 검증된 App Link / Intent |
| 외부 상태 | 코어 읽지 않음 | 코어 읽지 않음; NotificationListener 요청 없음 |
| 자체 오디오 | 플랫폼 오디오 세션/백그라운드 오디오 capability는 실제 재생 시에만 | 실제 재생에 필요한 media playback service·알림만, target SDK 요구 확인 |
| 파일(P3) | 시스템 파일 선택·sandbox 접근 수명 처리 | Storage Access Framework·persisted URI 권한 처리 |
| 미디어 보관함 | 코어 불필요 | 전체 저장소/전체 미디어 접근 권한 불필요 |
| 복원 검증 | 앱 종료/잠금/재부팅/시계 변경 | 동일 + 절전/OEM background restriction |

**배터리 유지 목적의 무음 오디오 재생 금지.** 외부 음악을 듣는 세션을 위해 자체 오디오 세션이나 foreground service를 불필요하게 띄우지 않는다. OS·스토어의 현재 규정은 구현 스파이크에서 다시 확인한다.

### 7.4 딥링크 안전성

- sourceType→approved URI 목록을 어댑터에서 관리한다. 사용자 입력 링크는 https 또는 명시적으로 허용한 서비스 scheme만.
- javascript:, file:, 임의 intent 및 임의 redirect chain은 거부한다.
- canOpen/resolve 결과는 힌트이며 성공 응답도 실제 음악 재생의 증거가 아니다.
- launch 요청·OS open 성공·사용자 복귀·실제 재생 시작은 서로 다른 사건이다. D0에서는 마지막 사건을 측정하지 않는다.
- 링크 실패 안내는 같은 세션·같은 소스에 한 번. 재시도는 사용자가 선택한다.

## 9. 데이터 모델·보존·호스트 인터페이스

### 9.1 논리 모델

아래 TypeScript는 프레임워크 선택이 아니라 데이터 계약의 표현이다. 모든 duration은 단위를 필드명에 넣는다.

	type TimerState = 'ready'|'running'|'paused'|'limit_reached'|'ended'|'recovery_required';
	type SourceType = 'external_d0'|'builtin_noise'|'local_o0'|'none';
	type Confidence = 'estimated'|'observed'|'manual'|'mixed'|'unknown';
	interface Allocation {
	  kind: 'bounded'|'infinite';
	  initialDurationMs: number|null;
	  currentTargetMs: number|null;
	  durationPerUnitMs: number;
	  loopDurationMs: number|null;
	  origin: 'manual_minutes'|'last_setting'|'history_suggestion';
	  targetRevision: number;
	}
	interface SessionCheckpoint {
	  schemaVersion: 1; sessionId: string; state: TimerState;
	  taskId: string|null; taskTitle: string|null;
	  allocation: Allocation; accumulatedActiveMs: number;
	  runningAnchorMonoMs: number|null; anchorWallEpochMs: number|null;
	  bootContinuityMarker: string|null; updatedAtEpochMs: number;
	  sourceType: SourceType; sourceConfigRef: string|null;
	  displayMode: 'playlist'|'single_loop'|'time_only';
	  confidence: Confidence; lastCueKey: string|null;
	  extensions: {addedMs:number; acceptedAtEpochMs:number}[];
	  sourceSegments: {type:SourceType; startActiveMs:number; endActiveMs:number|null}[];
	  correction: {anchorIndex:number; anchorActiveMs:number}|null;
	  deliveryId: string; resultFinalized: boolean;
	}
	interface LastTaskDuration {
	  taskId: string; lastActiveDurationMs: number;
	  updatedAtEpochMs: number; retentionConsent: true;
	}

O0 임시 모델: currentItemId, durationMs, positionMs, completedTracks, completedLoops, sequence, stale. 이 값은 메모리에서만 유지한다.

### 9.2 저장 규칙

| 데이터 | 저장 위치·수명(개발 기본안) | 전송 |
|---|---|---|
| 설정·선택 소스 | 기기 KV, 사용자가 삭제할 때까지 | 기본 전송 없음 |
| 활성 checkpoint | 원자적 로컬 저장. 7일 초과 시 자동 복원 금지 | OS 클라우드 백업 제외 |
| 곡·아티스트·아트·재생 위치·실측 완료곡 | 메모리만. 앱 종료 시 유실되면 unknown | 전송 없음 |
| 시간 중심 세션 결과 | 결과 화면 닫기까지. 복원본 최대24시간 | redacted 호스트 콜백만 |
| 작업별 마지막 시간 | 명시적 opt-in, taskId당1건, 30일 TTL | 기기 내만 |
| 생각 메모 | 결과 후 저장/삭제 선택. 미선택24시간 뒤 삭제 | 사용자 선택의 호스트 전달만 |
| 분석 이벤트 | 동의 시 허용필드만, 재송신 queue 최대7일 | 동의된 sink만 |

곡 메타데이터는 복원 편의를 위해서도 영속 저장하지 않는다. sourceConfigRef는 서비스 종류나 로컬 접근 토큰의 보안 참조이다. 사용자가 직접 저장한 실행용 플레이리스트 링크는 설정으로 분리하고, 실제 재생/청취 이력으로 취급하거나 분석 전송하지 않는다.

### 9.3 데이터 정책 상세

- 설정은 삭제 전까지 유지. 활성 checkpoint는 복원을 위해 기기 내 저장하고 OS 백업에서 제외한다.
- TTL은 다음 앱 실행/해당 저장소 접근 시 만료 확인 후 읽기 전에 삭제한다. 앱이 종료돼 있는 동안 정확한 시각에 물리 삭제가 실행된다고 보장하지 않는다.
- 활성 checkpoint가 7일 이상 오래되면 자동 측정 복원하지 않고 폐기/저장 지점 재개 선택을 제공한다.
- 곡 제목·아트·재생 위치·실측 카운트는 메모리에서만 유지한다. 재시작 뒤 복원 못한 실측을 거짓으로 채우지 않는다.
- 결과는 기본 당회 한정. 디스크 복원본의 최대 수명 24시간. 닫으면 삭제한다.
- 명시적 opt-in의 작업별 시간 1건은 30일 후 만료한다. 곡 수는 저장하지 않는다.
- 메모 보관은 세션 중 명시적 행동으로 간주한다. 결과에서 계속 저장/호스트 전달/삭제 선택. 미선택 24시간 뒤 삭제. 독립 앱에서 계속 저장을 선택한 메모는 사용자가 삭제할 때까지 유지한다.
- 작업명·메모·로컬 파일 URI는 민감한 사용자 데이터로 취급한다. 플랫폼 데이터 보호 저장소를 사용한다. 모든 외부 연결은 TLS.
- 오류·분석 SDK의 자동 화면 캡처/세션 리플레이는 기본 금지. 크래시 breadcrumb의 입력 문자열을 제거한다.

### 9.4 모듈 인터페이스

| 인터페이스 | 계약 |
|---|---|
| openSession(task?, settings, capabilities) | 진행 세션 있으면 복원, 없으면 배정 화면 |
| ClockPort | monotonic + wall + 연속성 검증. 테스트용 fake clock 주입 |
| StateStore | versioned read / atomicWrite / delete. 플랫폼 중립 |
| ExternalLauncher | canOpen / open만. play/pause/queue 메서드 없음 |
| OwnedAudioPlayer | load/play/pause/fade/setVolume, 앱 소유 소스만 |
| NotificationPort | schedule/cancel, 호스트가 유일한 OS 발송 주체 |
| EventSink | 동의·필드 허용목록을 통과한 제품 이벤트만 |
| onSessionResult | sessionId, deliveryId, taskId, initial/activeDurationMs, endReason, extensionUsed |
| onTransientDisplayResult | 선택 수신. confidence와 당회 곡/반복 표시값. **저장·분석 금지 계약** |
| onParkedThought | 사용자 요청 시 noteId/text. 분석 sink와 분리 |

결과 콜백은 exactly-once 전달을 가정하지 않는다. deliveryId로 수신 측 멱등성을 보장한다. 영속 재시도 payload에는 시간 중심 결과만 포함하고, 곡 수의 transient 콜백은 재시도 queue에 넣지 않는다. 기본 어댑터를 제공해 호스트 없이 동작하게 한다.

## 10. 분석·실험 이벤트

### 10.1 이벤트 분리

| 구분 | 이벤트 | 정책 |
|---|---|---|
| 로컬 내부 | mt_track_advanced / mt_track_corrected / mt_loop_completed | 메모리 UI bus만. 분석 SDK 연결 금지 |
| 동의 기반 제품 분석 | mt_allocation_declared / mt_session_started / paused / resumed / ended | 시간·상태·소스 대분류만 |
| 동의 기반 연결 진단 | mt_launch_panel_opened / mt_link_failed | provider enum, 실패 enum. URI·제목 제외 |
| 동의 기반 예고 | mt_last_track_notified | cue_kind, estimated bool, elapsed bucket. 실제 곡 수 제외 |
| 별도 연구 | task_action_confirmed / time_estimate_reported | 연구 동의·프로토콜에서만. 기본 상용 로그와 분리 |

- 공통 필드: eventId, schemaVersion, session-scoped pseudonymous ID, occurredAt, appVersion, OS major, sourceType, confidence.
- 분석에 taskTitle/taskId 원문, 메모, trackId/title, album, URI, 정확한 청취 이력은 포함하지 않는다.
- 동의된 서버 분석 데이터의 원시 보존은 기본30일, 집계 보존90일을 제안한다. 광고 ID·기기 지문을 만들지 않으며, 4주 유지율 연구는 별도 동의된 연구용 ID로만 연결한다. 서버를 도입하지 않으면 EventSink는 no-op이다.
- 동의 철회 시 미전송 queue 삭제. 이미 수집된 데이터 삭제 경로는 별도 개인정보 정책에 기재한다.
- 세션 종료 초과율은 내부 연구용 시간 기준 값으로만 검토. 무한·복구 불확실·목표연장 조건은 따로 분리하며 제품 UI 점수로 쓰지 않는다.
- 알 수 없는 음악 시작 시각·shuffle은 null. false/0으로 채우지 않는다.
- MT-H6의 음악 준비 시간은 D0 자동 로그만으로 측정 불가. 로컬 재생 이벤트 또는 별도 자기보고가 있는 세션만 분모에 포함한다.
- MT-H2는 start 버튼 지연과 실제 작업 착수 지연을 분리한다. 과제 행동 확인 없이 “착수 30% 개선”을 주장하지 않는다.
- 연구의 초과율은 정의·연장 조건·중도 종료 제외 기준을 먼저 고정한다. 제품 사용 로그만으로 인과 효과를 추정하지 않는다.

### 10.2 동의·식별자·삭제 수명

- ConsentRecord는 analytics/history/research 각각의 enabled, policyVersion, updatedAtEpochMs를 기기에 저장한다. 모두 기본 OFF. OS 알림 권한은 별도이다.
- 동의 이전 이벤트를 소급 수집하거나 나중 동의 후 재송신하지 않는다. 정책이 실질적으로 변경되면 해당 sink를 OFF로 두고 새 동의를 받는다.
- 제품 분석용 ID는 세션마다 새 무작위 ID이며 세션 간 연결하지 않는다. 광고 ID·하드웨어 ID·설치 지문을 대체 키로 쓰지 않는다.
- 4주 연구용 ID는 별도 연구 동의가 있을 때만 발급하고 종료/철회 시 폐기한다. 제품 분석용 ID와 자동 결합하지 않는다.
- 분석 철회는 신규 전송 즉시 차단 + 대기 queue 삭제. 이력 철회는 task별 저장값 삭제. 연구 철회는 연구 데이터 삭제 요청으로 이어진다.
- 서버/호스트 저장을 도입하려면 삭제용 무작위 receipt/token, 삭제 API, 처리 상태(pending/completed/failed)를 먼저 구현해야 한다. 해당 수단이 없으면 원격 EventSink는 **no-op**으로 유지한다.
- “전체 삭제”는 기기 데이터 제거와 함께 동의 범위 내 외부 sink에 삭제 요청을 보낸다. 오프라인이면 pending을 알리고 재연결 때 재시도한다. 서버 확인 전 “서버에서도 삭제 완료”라고 표시하지 않는다. 삭제 receipt에는 작업·곡·메모 내용을 포함하지 않는다.
- 사용자 요청으로 전달한 메모는 호스트 보관 정책과 삭제 경로를 전달 전 알린다. 모듈 로컬 삭제만으로 다른 앱에 저장된 메모까지 지웠다고 하지 않는다.

- iOS 터치 영역 최소44pt / Android48dp. 작은 링크도 hit area 확보.
- 본문 대비 최소4.5:1, 큰 텍스트3:1. 비텍스트 의미 요소3:1. 실제 렌더링 기준 검사.

- 바텀시트 focus trap, 닫은 후 호출 버튼으로 포커스 복원. 논리 읽기 순서 유지.
- 타이머 숫자는 tabular numerals 사용. 지원 여부를 실제 폰트로 테스트한다.
- 진동·소리·색상·애니메이션 중 하나에만 의존하지 않는다.

## 15. 릴리스 게이트와 남은 확인

### 15.1 코어 출시 체크리스트

- [ ] DEC-01(배정 도달), DEC-02(이력), DEC-04(무한), DEC-07(분석) 승인/수정 기록.
- [ ] 지원 OS 최소 버전·대표 기기·target SDK 확정. 제안값을 검증된 지원으로 광고하지 않음.
- [ ] 코어 FR/NFR 및 해당 QA 모두 통과. P3 미완료이면 로컬 메뉴 숨김 및 코어 출시임을 명시.
- [ ] 타이머 복구·알림 지연·오디오 인터럽트 실기기 스파이크 통과.
- [ ] 실제 외부 음악 재생 여부를 모르는 상태의 문구·아이콘 검수.
- [ ] 폰트 최종 승인, 파일 라이선스·배포/임베딩 고지 검토.
- [ ] 내장 오디오 생성 코드·샘플/효과 자산의 권리와 개인정보·스토어 정책 검토.
- [ ] 데이터 삭제·분석 동의·로그 redaction·호스트 계약 테스트.
- [ ] 효과·의학적 주장·정확도 보장·전 서비스 지원 보장 문구 없음.
- [ ] 별도 PRD의 P0 검증 게이트를 제품 책임자가 검토. 기능 QA가 MT-H2를 대체하지 않음.

### 15.2 외부 의존 [blocked]

이 문서 작성은 완료할 수 있으나 다음은 문서만으로 인증할 수 없다.

| 대상 | 미확인 사항 | 가장 작은 다음 검증 |
|---|---|---|
| 딥링크 [blocked] | 앱/OS별 현재 열기 동작 | 실제 기기에서 선택 서비스별 열기·실패 테스트 |
| O2 후속 [blocked] | 앱별 metadata·권한·Play 정책 | 별도 observer spike, 지원표 작성 |
| D1/D2 후속 [blocked] | 현재 플랫폼 정책·상용 권한·API 쿼터 | 최신 공식 정책 검토·필요 시 서면 확인 |
| 배터리/지연 [blocked] | 이 문서의 성능 예산 충족 여부 | release build로 고정 기기60분 시험 |
| 제품효과 [blocked] | 착수·잔여인지 개선 인과효과 | 동의된 검증 프로토콜 수행 |

### 15.3 명세의 변경 규칙

변경은 requirement ID를 유지하며 version·이유·관련 ADR·QA 영향을 기록한다. 정책 검토가 통과하기 전 O2/D1/D2를 디자인 화면만 보고 활성화하지 않는다. 제품 결정을 되돌리는 변경은 새로운 ADR 또는 PRD 개정으로 남긴다.
